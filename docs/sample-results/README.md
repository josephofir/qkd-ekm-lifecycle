# Sample results — verified run on Google Cloud (2026-08-19, region `me-west1`, simulator backend)

Redacted artifacts from one complete `scripts/run_experiment.sh all` against a deployment
created from scratch by a single `terraform apply` of this repository (commit `92da8c0`):

| File | What it is |
|---|---|
| `COMPARISON.md` / `.json` | 43 of 43 checks PASS against `expected/paper_numbers.json` and the paper's transcripts |
| `transcripts/s1.txt`, `s2.txt` | faithful redacted transcripts of the VPN (S1) and storage (S2) workflows, produced by `scripts/redact.py --check` from the raw service logs (compare with supplementary Figs. 5 and 8) |
| `continuity.json` | the lifecycle walk READY → BUFFERED → BINDING_HOLDOVER → SUSPENDED → RECOVERY → READY observed on the EKM's `/api/state` while the QKD source was interrupted and restored |
| `qkd_capture.json` | the simulator's HEQA-shaped capture (paper-calibrated rates; the paper's own device values live in `expected/qkd_capture_paper.json`) |
| `model/report.{json,md}`, `model/seeded.csv` | exhaustive enumeration: 45,824 states / 307,680 labeled transitions / depth 16, 0 violations, 13/13 seeded detections (the 11 MB `states.csv`/`transitions.csv` are regenerated by `uv run qkd-ekm-model all`) |
| `analysis/` | Table 9, scalars and Figures 4/5/12/13 regenerated from the paper's captured operating point |

Not published from the run: `raw/` service logs and `s2/` (unredacted identifiers), `env.json`
(project identifiers). Clock offsets of a few milliseconds between VMs are visible in the
transcripts; `compare.py` therefore checks ordering per component (see
`docs/evidence-schema.md`). The S2 transcript also shows the external-key rotation the runner
triggers before the upload (`Rotated external key to version v4`), after which Cloud Storage
wraps the new object's DEK through the EKM (`Got Key Wrap request`).
